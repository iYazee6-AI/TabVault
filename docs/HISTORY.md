# TabVault decision log

## 2026-09-17 — Design

- Request: a tab manager like Tab Manager v2 (https://github.com/xcv58/Tab-Manager-v2)
  with export of all windows and tabs with full details.
- Decisions: build our own in plain JS rather than fork (no React/MobX
  toolchain); JSON export only for v1; restore from JSON with lazy-loaded
  tabs; full-page UI in its own tab; features: all windows/tabs view with
  search, bulk move/close, native tab groups, duplicate cleanup; automatic
  snapshots taken on change (debounced), not on a timer.
- Spec: `docs/superpowers/specs/2026-09-17-tabvault-design.md`.

## 2026-09-17 — 1.0 build

Eight tasks, subagent-driven, a review per task. Rulings that changed the plan:

- Change debounce uses a re-armed `chrome.alarms` alarm (MV3 workers cannot hold a 30 s timeout); 30 s minimum.
- Title changes are not a snapshot trigger (starvation by live titles); mute changes are; `stripVolatile` sorts windows by id.
- Page: column scroll preserved, keyboard cursor skips hidden rows, close-window label uses the unfiltered count, group rename survives re-renders (editing flag, always cleared), move/drop/group failures toast.
- Restore executor skips every step of a window whose creation failed instead of acting on the current window.
- e2e scenario I was found to be scored PASS on indirect evidence because `chrome.tabs.discard` crashes Playwright's Chromium; ruled: add a real `lazyRestore` setting, split I into I-a (full restore verified with lazy off) and I-b (PASS or LIMITED), statuses LIMITED/NOT RUN, worker handle re-acquired.
- Final review (with fixes): finite-bounds check, windows.create retry without URL, discard-failure summary, state-held close confirmation, stable move-target options, select-open render guard, error toasts, non-normal windows excluded from move targets, incognito move guards, 50 MB import cap, max-wait cap for change snapshots, `storageVersion` and favicon trimming, doc reconciliation.
- Parked at merge: see CLAUDE.md follow-ups.

Result: 23 unit tests, 13 e2e scenarios (I-b PASS or LIMITED depending on the environment crash).

## 2026-09-28 — 1.1 "Console" UI

- Request: the owner tried the 1.0 store build and asked for better UI/UX. Three mockups; direction A, "Console", chosen (dense, keyboard-first, mono for names and counts, one amber for the thing to press). Spec: `docs/superpowers/specs/2026-09-28-console-ui-design.md`; plan: `docs/superpowers/plans/2026-09-28-console-ui.md`.
- Tokens exactly as the spec's table, light and dark, following Chrome's scheme with an Appearance override (System/Light/Dark). IBM Plex Sans 400/500/600 and Plex Mono 500 bundled in `app/fonts/` with the OFL 1.1 licence; `tools/pack.js` refuses to build without them. TabVault sends nothing to any server of its own and has no analytics; the only network activity is the browser fetching each tab's favicon from that tab's own site, which 1.0 did too (the whole-branch review's M3 corrected an earlier "no network requests" claim here, in the listing, PRIVACY.md and the README).
- Window cards in a responsive grid (3/2/1 columns), the window hosting TabVault marked CURRENT, window names editable inline, kept in `chrome.storage.local` under `windowNames` and cleared by the worker on `chrome.runtime.onStartup` (the spec said `chrome.storage.session`; Task 2's review found Chrome also wipes session storage on an extension update or reload, while window ids only reset with the browser), and carried into snapshots and exports as the optional `windowName` (schema stays 1; restore re-applies names with a `nameWindow` step).
- Groups: colour dot, 3 px bar, eight-dot picker. Tab rows: favicon or a letter badge coloured from the domain (`lib/ui.js`), domain in mono, flags (pinned, audible, muted, `zz`, `dup`), the active-tab bar.
- Floating bulk bar with a Move-to menu; Esc closes a menu first, then clears. One shortcut table (`lib/shortcuts.js`) drives the key handler, the hint strip and the `?` panel; new keys `j` `k` `x` `g` `d`.

- Store screenshots regenerated in the new look (light theme, RGB without alpha, written by `tools/screenshots.js` itself).
- Pre-upload additions (branch `feature/about-and-dup-choice`): the duplicates dialog now closes only the extra copies you tick (a Keep radio per copy as in 1.0, defaulting to the `lib/dedupe.js` pick, which is unchanged; a close checkbox on every other copy, all ticked on each draw including after toggling Ignore #hash; changing Keep moves the kept marker and gives the previously kept copy a ticked checkbox; Select all / Select none; a `Close N selected` button disabled at 0); an About dialog in the ⋯ menu (version from the manifest, repository, issues and privacy links, font credits, nothing fetched) and `homepage_url` in the manifest. e2e scenarios S (About) and T (per-row duplicates) added; G now uses the new button label.

## 2026-11-08 — 1.3.0 "Shelf" (built, not merged)

- Request: the owner's word "tabvault 1.3 build" on Wakeel's brief, the spec with Wakeel's rulings (a shelving rule closes tabs only once the user dry-ran it and switched it on; the promise "Nothing is closed unless a rule you wrote says so"; screenshot 04 becomes the palette's Saved section). Plan: `docs/superpowers/plans/2026-11-08-tabvault-1-3-plan.md`. Branch `feature/1.3-shelf` from main 487e8d7, built on Opus test first; Naqid reviews before any merge, feature 1 first.
- Idle rules: `settings.idleRules` (pattern, 15 minutes to a day, unload / shelve / never, the shelf, on, `previewedFor`), first enabled match wins, the global Unload idle tabs setting for tabs no rule matches. `planIdle` in `lib/discard-rule.js`: the 1.2 exemptions for every action, never incognito by a rule, the global keep-pinned wins, 25 a run with unloads first, the last tab of the last normal window unloaded instead of shelved. The dry run runs in the worker (it sees every tab) and unlocks the switch for the current pattern and time; above 50 matches a second "Allow it". `*.com`, `*.co.uk`, `*.com.sa` and the like are refused (a short two-level suffix list). The 1.2 allowlist became `never` rules once at worker start (`idleRulesVersion: 1`); the key is kept one release.
- Shelves: `lib/shelves.js`, chunks of 200, the count derived; the worker writes, reads back, then closes (`executeShelve`); a failed write closes nothing. The Recently closed entry is tagged with the shelf through the existing `onRemoved` path ("shelved to ..."), and nothing is recorded when the list is off. The page lists the shelves under Recently closed (Open into the item's group, joined or recreated by title and colour; Open and remove; Remove; Open all; Export; Delete, asked with the count, refused while a rule points at the shelf). "Move to shelf" in the selection bar and the palette.
- Compare a snapshot with now (`lib/diff.js`): by normalised URL and multiplicity, windows matched by name then overlap; missing, new since, moved; Reopen into a new window or into the matched windows; Select all new. From a snapshot row's Compare and the palette.
- Saved search (`lib/saved-index.js`): snapshots, shelves and recently closed in one in-memory index (one row per URL, the newest, "+N older"); `s:`, `t:`, `a:`; highlights as `<mark>` text nodes; Enter opens or focuses an open copy, Shift+Enter in a new window, "Open all" in one new window through the restore path (asks above 20).
- Markdown export and import (`lib/exporters.js`): the Export dialog picks this session, the selected tabs, a snapshot or a shelf, JSON or Markdown, Download or Copy to clipboard (`writeText` from the click, a selected textarea when refused, no `clipboardWrite`). Import takes a file or a paste with a live preview; JSON and Markdown both drop links that are not web pages and say how many; above 100 tabs it asks again; `file:` links are skipped and said when file access is off.
- Deviations from the spec, small: "Run idle rules now" applies the global unload setting only when it is on (the alarm's behaviour), so a manual run never unloads tabs the user did not ask for; the palette's 1.2 "Discard idle tabs now" keeps forcing it. The derived item count sums the chunk lengths (equal to the spec's formula whenever the middle chunks are full, and right in between). A shelf that a rule points at cannot be deleted (the spec left that case open). Items carry an `id` so one can be removed without rewriting its neighbours.
- Store: version 1.3.0, no new permission; the description's promise "Nothing is closed unless a rule you wrote says so"; the `tabs`, `alarms` and `storage` justifications and the single purpose reworded; the Web history disclosure names the shelves; section 14 holds the NEW IN 1.3 block and the three real-install checks. Screenshots: 03 is now the rules block with a dry run (`03-idle-rules.png`), 04 the palette's Saved section (`04-saved-search.png`); `04-duplicates.png` and `03-unload-idle-tabs.png` retired. `PRIVACY.md` gained Shelves, the idle rules and the in-memory search.
- For the owner's hands before upload: the three checks in the listing's section 14 (clipboard, a shelving rule at 15 minutes, a shelved item whose group is gone).
- Naqid's review (fix first, the same day), each fixed with a test: (1) the dry-run key covers the action too (`pattern|idleMinutes|action`), so changing Unload or Never to Shelve relocks the switch and brings back the preview and the 50-tab question (e2e AA: an Unload dry run on 60 more tabs, then Shelve, stays locked); (2) `hostOf` gives a host only to http and https pages, so `file://server.local/share` never matches a rule; (3) shelved tabs are closed one by one (`closeEach`), so a tab the user closed meanwhile no longer leaves the others open with their items already shelved; (4) a tab still loading, or known only by its `pendingUrl`, is exempt; (5) a Unicode pattern is accepted and stored in its ASCII form; (6) Markdown import drops a link whose destination is followed by text (`[x](https://a.com/a b)`) instead of cutting it (a double-quoted title, `[t](url "title")`, is kept, as notes apps write it), and the link scan is one linear pass.
- Naqid re-review: ship. Two small items taken: a dry-run result that comes back after the values changed is not shown, and "Allow it" unlocks only the values that were dry-run (`allowLargeKey`, with a test).
- Result: 123 unit tests (from 71; new files `test/idle-rules.test.js`, `test/shelves.test.js`, `test/diff.test.js`, `test/saved-index.test.js`, and more in exporters, settings, recent, discard-rule); 32 e2e scenarios (AA rules and dry run, AB shelves, AC compare, AD saved search, AE Markdown added; I-b and Z PASS or LIMITED as before); lint 0 errors; `npm run pack` builds `dist/tabvault-1.3.0.zip` (32 files, only `manifest.json`, `background.js`, `app/`, `lib/`, `icons/`); `manifest.json` permissions unchanged.
