# TabVault decision log

## 2026-09-17 — Design

- Request: a tab manager like Tab Manager v2 (https://github.com/xcv58/Tab-Manager-v2)
  with export of all windows and tabs with full details.
- Decisions: build our own in plain JS rather than fork (no React/MobX
  toolchain); JSON export only for v1; restore from JSON with lazy-loaded
  tabs; full-page UI in its own tab; features: all windows/tabs view with
  search, bulk move/close, native tab groups, duplicate cleanup; automatic
  snapshots taken on change (debounced), not on a timer.
- Spec: `docs/superpowers/specs/2026-09-17-tabvault-design.md`.

## 2026-09-17 — 1.0 build

Eight tasks, subagent-driven, a review per task. Rulings that changed the plan:

- Change debounce uses a re-armed `chrome.alarms` alarm (MV3 workers cannot hold a 30 s timeout); 30 s minimum.
- Title changes are not a snapshot trigger (starvation by live titles); mute changes are; `stripVolatile` sorts windows by id.
- Page: column scroll preserved, keyboard cursor skips hidden rows, close-window label uses the unfiltered count, group rename survives re-renders (editing flag, always cleared), move/drop/group failures toast.
- Restore executor skips every step of a window whose creation failed instead of acting on the current window.
- e2e scenario I was found to be scored PASS on indirect evidence because `chrome.tabs.discard` crashes Playwright's Chromium; ruled: add a real `lazyRestore` setting, split I into I-a (full restore verified with lazy off) and I-b (PASS or LIMITED), statuses LIMITED/NOT RUN, worker handle re-acquired.
- Final review (with fixes): finite-bounds check, windows.create retry without URL, discard-failure summary, state-held close confirmation, stable move-target options, select-open render guard, error toasts, non-normal windows excluded from move targets, incognito move guards, 50 MB import cap, max-wait cap for change snapshots, `storageVersion` and favicon trimming, doc reconciliation.
- Parked at merge: see CLAUDE.md follow-ups.

Result: 23 unit tests, 13 e2e scenarios (I-b PASS or LIMITED depending on the environment crash).

## 2026-11-17 — 1.6.0: bookmarks (built, not merged)

- Request: the owner's words through Wakeel's brief (job tabvault-bookmarks, word "tabvault bookmarks build"): give TabVault access to bookmarks; "delete" must really move the bookmark into a folder called Deleted (made when missing); let the user save his bookmarks with their folders; restore may come later. Branch `feat/bookmarks-1.6` from main 9a54845 (1.5.0), in its own worktree; Naqid reviews before any merge.
- Headless first: `e2e/run.js` takes `TABVAULT_HEADLESS=1` (channel `chromium`, `--screen-info`), as `tools/screenshots.js` does, and every browser run of 1.6 used it; no window opened on the owner's screen.
- Permission: `bookmarks` in `optional_permissions` only (a new required permission would disable the extension for every existing user until accepted). `settings.bookmarks` (false by default) is the user's switch; the feature runs only while it is on AND Chrome has granted the permission (`state.bm.on` in the page, `bookmarkContext` in the worker), so a permission withdrawn at chrome://extensions turns everything off. The Settings switch calls `chrome.permissions.request` inside the change event (nothing awaited first) and, off, saves the setting and then `chrome.permissions.remove`. Off, nothing bookmark-related is drawn and no bookmark API is called.
- The rule, in one place: `lib/bookmarks.js` `moveToDeleted` is the only removal. It never calls `remove` or `removeTree`: callers get the API only through `safeBookmarks`, a frozen object of nine methods without either. The Deleted folder is under Other bookmarks, found by the stored id `bmDeletedFolderId` (even renamed), then by its name, else made; a folder the user deleted is made again. Each moved item keeps its title and address; where it came from (`parentId`, `index`, the folder path, the time) is written to `bmTrash` in storage.local, keyed by bookmark id, before the move, and dropped for a move that fails and once the user empties Deleted or moves the item back. Top folders, managed (unmodifiable) nodes, Deleted itself and what is in it are skipped; a folder moves whole. TabVault offers no way to empty Deleted. Tests: `test/bookmarks.test.js` fails when any source file (comments aside) calls `bookmarks.remove`, `removeTree` or names them by string, and the fake chrome.bookmarks (`test/fake-bookmarks.js`) throws and records any call to either, every test asserting none; e2e AH stubs both in the worker and the page and counts zero calls.
- Writes run in the worker's `bookmarkWrite` queue (messages `bmMoveToDeleted`, `bmSaveFolder`, `bmBackup`); the page reads through `safeBookmarks` (the palette's in-memory index, duplicates, the HTML export).
- Backups: `takeBackup` flattens the whole tree in tree order (each folder before what it holds: `id`, `parentId`, `index`, `title`, `url`, `dateAdded`, `dateGroupModified`, `folderType` of the top folders), writes it as `bmBackup:<id>:<n>` chunks of 500 nodes, reads every chunk back and checks each node, and only then puts its metadata (`takenAt`, `reason`, counts, `chunks`, `schema: 1`) at the head of `bmBackupIndex`; the oldest beyond `settings.bookmarkBackupsKeep` (5, 1 to 50) are dropped. A backup is taken by `moveToDeleted` and `saveTabsAsFolder` themselves before a change to more than 10 bookmarks (a folder counts with all it holds), and a failed backup stops the change. Back up now downloads the same nodes nested (`format: "tabvault-bookmarks"`, `roots`); Export as HTML writes the Netscape bookmarks file every browser imports.
- Restore is not built (the owner: "later, maybe"). The stored shape is made for it: the top folders are matched by `folderType` (or their place), and the list can be recreated parents first in order, mapping the old ids to the new ones; `bmTrash` gives the origin of each deleted item for a put-back. The dialog lists the backups with date, counts and reason and says restore is coming.
- Search: `b:` (`parsePaletteQuery`) and every palette query list bookmarks (★, the folder path, title and address matched as the saved search matches them) and folders (▤, "Open folder ... as a window", its web pages including subfolders, through the restore path, a second Enter above 50); the Deleted folder is left out. Enter opens (or focuses an open copy), Shift+Enter in a new window; the × on a row moves it to Deleted. Duplicates group by the normalised address with the ignore-hash setting, oldest first, nothing pre-ticked ("Tick all but the oldest" is a button).
- Save as bookmark folder: the ☆ on a window card and a group header, "Bookmark" in the selection bar and on a shelf, and the palette; a folder inside Other bookmarks › TabVault (stored id `bmTabVaultFolderId`, then the name); only http, https and file links (`isWebPage`), the rest counted as skipped.
- Decided differently from the brief, small: (1) a stored setting plus the permission, not the permission alone, decides "on" (it lets the harness, where the permission is granted at install, walk the off path, and a granted permission left by an older install does not switch the feature on by itself); (2) the stored Deleted folder still counts when the user renamed it (the brief's "by a stored id first"); (3) "Open a folder" takes the pages of its subfolders too, in tree order; (4) the bulk count includes folders, so moving a folder of 10 links takes a backup.
